# Reproductive 4.0.1

Доработка расширения Reproductive для SillyTavern на основе версии 3.14.0-cycle.11 (автор исходного расширения — MomCta). Лицензия исходного проекта сохранена в LICENSE.

## Исправления после проверки 4.0

Список исправлений и сравнение промптов — в AUDIT-4.0.1.md.

## Обновление

1. Остановите SillyTavern. Сохраните копию папки установленного расширения и резервную копию настроек SillyTavern.
2. Распакуйте архив. Скопируйте **содержимое папки Reproductive** в папку уже установленного расширения, заменив одноимённые файлы. Сохраните прежнее имя папки. Не устанавливайте вторую копию рядом с первой.
3. Запустите SillyTavern и полностью обновите страницу.
4. Откройте настройки расширения → **«◷ Раса, цикл и беременность»**. Там отдельные настройки персоны и персонажа.

Для новой установки папка с manifest.json и index.js должна находиться непосредственно внутри public/scripts/extensions/third-party/. Архив сам по себе не является ссылкой для установки через Git.

Ключ сохранений `reproductive-system` прежний. Существующие дети, беременности, контрацепция и история чатов сохраняются. Старые роли альфа/бета/омега больше не управляют биологией. Проверьте нужные расовые особенности после обновления.

## Что изменилось

- Четыре типа цикла: с менструацией, без кровотечения, с течкой, без цикла. Длина и дни кровотечения задаются отдельно для каждого участника; доступны пресеты.
- Течка и гон независимо включаются как особенности расы. По циклу или ежегодной дате ММ-ДД в РП-календаре. Без сюжетной даты сезонные периоды не запускаются. Реальные паузы не двигают время.
- Длительности 1, 3, 7, 30 дней и свой вариант. Для циклического периода длина ограничена длиной цикла минус один день. Для сезонного — до 364 дней, чтобы до следующего ежегодного периода оставался хотя бы один день. Сезонный интервал использует календарные даты, включая переход через Новый год.
- Течка: 90% по умолчанию, вне течки 0%, 5% или своё значение. Гон: множитель по умолчанию либо фиксированный шанс. Несовместимость и контрацепция сохраняют приоритет; явно заданное нулевое окно не обходится гоном.
- Готовые и собственные проявления для течки/гона. Свои теги: `Название | описание`, по одному на строке. Более пяти — предупреждение, а не запрет. Модель получает правило проявлять 1–2 признака по ситуации.
- Одна шкала нагрузки 0–100. Новые события стресса, болезни, недоедания, травмы, переутомления повышают её; отдых и питание снижают. Значения — игровые условности.
- При 100: один исход 50/50. Потеря остаётся незавершённым событием до завершения по сюжету; при спасении требуется отыгранная помощь, затем нагрузка 70 и высокий риск. Повторных бросков во время события нет. Расширение не телепортирует к врачу и не выбирает эмоции игрока.
- Замирание: отдельное сохраняемое состояние, уведомление и короткая строка для модели. Развитие остановлено, но беременность физически не сбрасывается до окончания события. Есть ручная установка. Модель может уточнить уже выпавшую потерю как замирание, но не может создать дополнительную случайную потерю.
- Гибель вынашивающего персонажа отключена по умолчанию. Отдельный переключатель разрешает фиксировать **уже установленную в сцене** гибель. Дополнительного несогласованного случайного броска нет. Отдельная механика потери одного плода не добавлена.
- Обследования: один набор бросков на триместр, условные шансы 30% → 15% → 1%; следующий бросок только после успеха предыдущего. Максимум три новых диагноза. Это вероятность игровых событий, не медицинская статистика.
- 22 обычных варианта осложнений по этапам и неограниченный список своих. Обычные пункты можно отключать по одному или целиком. Свои: `Название | описание | 1,2,3`, по одному на строке.
- Расширение определяет число осложнений; модель выбирает подходящие варианты с учётом известного здоровья, срока и обследования. Диагнозы не исчезают из-за повторного визита. Уже активные сохраняются между триместрами.
- Дата следующего приёма и имя врача. Напоминание в состоянии для модели по наступлении РП-даты; само обследование не происходит автоматически. Кнопка «Обследование состоялось» нужна после отыгранного приёма, а не для мгновенного лечения.
- Результаты обследований и кризисов повторно используют сохранённые броски при перегенерации. Ручные изменения обновляют снимок состояния.

Настройки профилей действуют в настройках расширения отдельно для персоны и персонажа. Состояния беременности, обследований и нагрузки хранятся отдельно по чатам и носителям.

## Оформление

Матовые кремовые и тёмные поверхности, без градиентов. Текст Arial/Verdana 16, 18 или 20 px, межстрочный интервал 1.6, свободные интервалы, выравнивание влево. Символы сопровождаются подписями. Основные элементы управления не ниже 44 px. Видимый клавиатурный фокус, нативное модальное окно с Escape, перенос сетки в одну колонку на узком экране, поддержка уменьшения движения. Дополнительные настройки раскрываются по необходимости.

Ориентиры:
- https://dyslexiascotland.org.uk/dyslexia-friendly-typed-formats/
- https://design-system.service.gov.uk/components/details/
- https://design-system.service.gov.uk/components/text-input/

Настройка размера важнее обещания универсального «шрифта от дислексии»: комфорт чтения индивидуален. Старый пользовательский CSS может потребовать ручной корректировки.

## Протокол модели

Используется существующий скрытый `RP_STATUS`. Поле `care` относится к персоне, `partner.care` — к персонажу:

- `event`: только новое событие в сцене (`stress`, `illness`, `starvation`, `injury`, `exhaustion`, `rest`, `nutrition`). Не повторять в каждом ответе описание продолжающегося состояния.
- `screening: true`: состоялось подходящее обследование.
- `diagnoses: ["id"]`: заполнить только запрошенное расширением число слотов из допустимого списка.
- `resolved: ["id"]`: установленное в сцене выздоровление по уже существующему диагнозу; не удаляет запись обследования.
- `help_completed: true`: помощь для сохранения беременности действительно завершена.
- `loss_form: "frozen"`: уже подтверждённая системой потеря проявляется как замирание.
- `loss_completed: true`: событие потери физически завершилось по сюжету.
- `maternal_death_confirmed: true`: только уже установленная в сюжете гибель и только при включённом разрешении.

Состояние трекера само по себе не является знанием персонажей. Обнаружение зависит от наблюдаемых признаков, обследований, раскрытия или установленных способностей мира.

## Проверка и ограничения

Синтаксис всех JS-модулей проверен. 51 автоматическая проверка правил и связей между настоящими модулями проходит на Node.js 24:

```
node --experimental-vm-modules --test tests/*.test.mjs
```

Проверены длинные и независимые циклы, сезонная дата без реального времени, переход года, совместимость, нулевое окно, ограничение диагнозов, сохранение осложнений, однократность нагрузки, перегенерации, обе ветки кризиса, блокировка родов при потере, независимость носителей, инжекты и экранирование полей.

В установленной пользовательской SillyTavern эта версия пока не запускалась. Визуальная браузерная проверка в среде сборки была недоступна: локальный Chromium не запускается, удалённый браузер не имеет доступа к тестовому серверу. Адаптивные стили реализованы, но их реальный вид и совместимость с вашей темой требуют проверки после установки. Полное соответствие WCAG не заявляется.

Единый разбор РП-даты и времени намеренно не переработан: сохранён существующий парсер. Диагностический полный перескан не пересоздаёт уже сохранённые кризисы, нагрузку и результаты обследований; при наличии этих данных обновляется только последний ответ.

Если модель не передаёт нужный скрытый маркер события, состояние не обновится автоматически; для обследования и завершения кризиса есть ручные кнопки.
